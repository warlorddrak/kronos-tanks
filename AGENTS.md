# AGENTS.md — Developer & AI Agent Guide for Kronos Tank Logs

## Overview

**Kronos Tank Logs** ([kronos-tanks.com](https://kronos-tanks.com)) is an automated tracking and leaderboard system for tank performance in World of Warcraft (Vanilla) raid encounters on the Kronos private server (specifically Kronos V).

- **Data source**: [Twinhead](https://vanilla-twinhead.twinstar.cz/?latest=bosskills) (TwinStar database).
- **Data store**: Flat-file JSON database `bosskills.json`.
- **Frontend**: Single static file `index.html` generated by `render.ts` and hosted on GitHub Pages.
- **Automation**: GitHub Actions workflow running every 5 minutes to scrape new kills, update the JSON store, and regenerate the site.

---

## Tech Stack & Architecture

- **Runtime**: [Bun](https://bun.sh/) (>= 1.3.0). Zero-config TypeScript execution without `package.json` or `node_modules`.
- **Language**: TypeScript (native ESM, strictly typed interfaces).
- **Network / Scraping**: Fetch API with automatic `curl` subprocess fallback to bypass Cloudflare bot challenges.
- **Hosting / Deployment**: GitHub Pages with custom domain `CNAME`: `kronos-tanks.com`
- **CI/CD**: GitHub Actions `.github/workflows/scrape-bosskills.yml` on a `*/5 * * * *` cron schedule.

## Repository Structure

| File | Purpose |
| --- | --- |
| `scrape-bosskill.ts` | Scrapes and parses a single bosskill encounter page (`?boss-kill=<id>`) from Twinhead. Implements Cloudflare-resistant fetching and tank identification logic. |
| `scrape-bosskills-for-day.ts` | Scrapes the bosskills catalog list (`?latest=bosskills`), filters by date, and performs concurrent scraping for historic or date-bounded runs. |
| `update-bosskills.ts` | Main updater script executed by CI. Reads `bosskills.json`, finds new bosskills (IDs strictly greater than max recorded ID), scrapes them concurrently, merges records, writes to disk, and calls `render()`. |
| `render.ts` | Static site generator. Transforms `bosskills.json` into `index.html` with leaderboards (Top 10 DPS per boss), recent kills feed, tab filtering, and responsive styling. |
| `bosskills.json` | The primary data store containing historical bosskill records and extracted tank stats sorted descending by kill ID. |
| `index.html` | Generated static HTML file deployed to GitHub Pages. Contains embedded CSS and minimal client-side vanilla JavaScript for filtering. |
| `CNAME` | Custom domain configuration for GitHub Pages (`kronos-tanks.com`). |
| `.github/workflows/scrape-bosskills.yml` | Scheduled GitHub Actions workflow that runs every 5 minutes using Bun, commits changes, and pushes to `master` with `[skip ci]`. |

## Domain Rules & Business Logic

### 1. Tank Identification
In Vanilla WoW logs without explicit role tags, tanks are identified programmatically:
- **Total Mitigated Damage**: Each player's candidate score is calculated as `dmg_taken + dmg_absorbed`.
- **Primary Tank**: The player with the highest total mitigated damage (`> 0`) is selected as the encounter's primary tank.
- **Class Eligibility**: All classes are eligible (Warriors, Druids, Paladins, etc.), though Warriors represent the vast majority in Vanilla raid logs.

### 2. Survival Requirement
- If the identified primary tank died during the fight (`deaths > 0`), the encounter is **disqualified** from tank leaderboards (`tanks` array is left empty).
- Death counts are parsed from the Twinhead timeline chart data (`chart_data[4]`, the death event series).

### 3. Leaderboards
- Boss leaderboards group surviving tanks by `boss_name`.
- Tanks are ranked strictly by **DPS descending**.
- Each boss card displays the Top 10 tanks of all time for that encounter.

### 4. Realm Filtering
- The scraping pipeline captures bosskills from all realms reported by Twinhead.
- Rendering defaults to the active realm `KronosV` (`bun run render.ts bosskills.json index.html KronosV`).

## Core Data Schemas

### `Tank` (`scrape-bosskill.ts`)
```typescript
export interface Tank {
    boss_name: string;
    guid: string;
    realm: string;
    name: string;
    class: string;           // Numeric WoW class ID (e.g., "1" = Warrior, "11" = Druid)
    avg_item_lvl: string;
    dmg_done: string;
    dmg_taken: string;
    dmg_absorbed: string;
    dps: string;
    deaths?: number;         // Must be 0 for qualifying records
}
```

### `StoredBosskill` (`update-bosskills.ts`)
```typescript
export interface StoredBosskill {
    id: number;
    boss_name: string;
    raid: string;
    guild: string;
    realm: string;
    time: string;            // Format: "YYYY/MM/DD HH:mm:ss"
    tanks: Tank[];           // Empty array if no qualifying tank or tank died
    error?: string;          // Scraping error message if failed
}
```

## Commands & Workflows

All commands are executed using `bun` from the repository root:

### Update Pipeline (Incremental scrape + render)
```bash
bun run update-bosskills.ts
```
Fetches the latest catalog from Twinhead, scrapes any bosskill with an ID higher than the current maximum in `bosskills.json`, updates `bosskills.json`, and triggers `render()`.

### Render HTML Only
```bash
# Default (bosskills.json -> index.html for KronosV)
bun run render.ts bosskills.json index.html KronosV

# Render all realms
bun run render.ts bosskills.json index.html all
```

### Scrape a Single Bosskill
```bash
# Test scraping a specific bosskill ID (outputs JSON to stdout)
bun run scrape-bosskill.ts 944440
```

### Scrape Bosskills for a Specific Date
```bash
# Scrapes all bosskills for a given day (YYYY-MM-DD or YYYY/MM/DD)
bun run scrape-bosskills-for-day.ts 2026-09-26
```

## Scraping & Network Resilience

Twinhead is protected by Cloudflare bot mitigations. The fetching logic in `scrape-bosskill.ts` handles this via a dual-layer strategy:
1. **Standard `fetch`**: Attempts standard HTTP request with realistic browser headers (`User-Agent`, `Referer`, `Accept`, etc.).
2. **`curl` Subprocess Fallback**: If Cloudflare serves a challenge page (`<title>Just a moment...</title>` or `cf-mitigated`), `fetchHtml` spawns a `curl` process via `Bun.spawn` with identical headers and HTTP/2 decompression.
3. **Data Extraction**:
   - Encounter participant stats are parsed from the embedded script `var bosskillData = [...]`.
   - Death timelines are parsed from `var chart_data = [...]` (series index 4).
   - Boss name is parsed from the breadcrumb table or anchor tag `?npc=...`.

## Guidelines for AI Agents

When working on this codebase, observe the following rules:

1. **No Package Manager Bloat**:
   - Do NOT introduce `package.json`, `node_modules`, or complex build tooling unless explicitly instructed.
   - Bun executes all TypeScript files directly and instantaneously. Keep it lean and dependency-free.
2. **Preserve Rendering Determinism**:
   - `render.ts` generates the production `index.html`.
   - If modifying HTML or CSS, edit `render.ts` and verify by running:
     ```bash
     bun run render.ts bosskills.json index.html KronosV
     ```
   - Only the generated timestamp in the footer should differ if no template or data logic changed.
3. **Non-Destructive Failures**:
   - If Twinhead fails to respond or changes page layout, scripts must fail gracefully without wiping or corrupting `bosskills.json`.
   - The 5-minute cron pipeline relies on idempotency: if an update cycle fails, existing records must remain intact.
4. **Git & CI Conventions**:
   - Commits containing automated updates should include `[skip ci]` in the commit message to prevent recursive GitHub Action triggers.
   - Maintain documentation integrity and keep existing comments intact.
